# Evela

A native Go/Fyne desktop analyzer for EVE Online game logs. It reads every character from the logs' `Listener` headers and graphs incoming and outgoing damage separately, with a consistent color per character.

## Run

Open `evela.exe`, or run the project with:

```powershell
go run .
```

The default folder is your Windows Documents known folder (including redirected/OneDrive Documents), under `EVE\logs\gamelogs`. Use **Browse** or enter another path and choose **Open folder** to change it. Logs are read locally and are never modified or uploaded.

**Settings → Log loading…** controls how old a log file may be loaded. The default is **30 days**, measured from the current UTC date. The inclusive cutoff uses the first eight digits and underscore in each filename: `20261018_025902_2123143905.txt` is October 18, 2026. For example, on October 18 the default includes files dated September 18 or later, including all newer dates. This filter uses neither file modification times nor timestamps inside a file. Files older than the cutoff and files without a valid `YYYYMMDD_` prefix are skipped before being opened or parsed. Choose another number of days or **Load all log files** to include an older archive or renamed files. **Save and refresh** saves the preference for future launches and queues an immediate reload, even with automatic refresh disabled. The graph's **All history** preset covers the loaded files; it does not override the loading limit. No log files are deleted.

The first import scans eligible `.txt` logs in that folder. A large archive may take a little time; a progress indicator shows the import. Later refreshes use an in-memory cache and only reparse changed or new files. Files that age out or are excluded by a narrower loading limit are also removed from the cache. **Auto refresh** checks every ten seconds and advances the cutoff with the current date. Refresh details report the loaded count and files skipped for age or unrecognized filename dates. Refresh messages and progress appear beneath the refresh controls in reserved space, so updates do not shift the graphs. **Details…** opens the full message, including any file warnings. ESI refresh messages also keep a stable height and have a details dialog. Refreshes preserve character, ship and token list scroll positions. The cache lasts until you close the app.

## Use

- **Damage graphs:** separate incoming and outgoing DPS timelines for all selected characters. Match each line to the color beside its character. Hover to inspect a time bucket's three highest rates; each character or ship-group reading uses the same color as its plotted line. The UTC timestamp stays neutral, and long readouts are clipped within the graph header. Drag horizontally inside either plot to highlight a time range, in either direction, then release to zoom both graphs and the damage totals into that range. Selection updates the UTC fields and switches to **Custom UTC range**, so refreshes retain it. Ranges include the selected seconds; tiny movements and ordinary clicks do not zoom. **Ctrl+Z** undoes a graph range change; **Ctrl+Y** reapplies an undone change. On Windows, mouse **Back** and **Forward** do the same undo/redo within the Evela window, using the same history as the keyboard shortcuts. Multiple selections can be undone/redone in order, restoring both graphs, totals, UTC fields and the previous preset. New drag selections discard the redo branch. Refreshes preserve history; manually editing dates, choosing another preset or loading another log folder starts new history. Text fields retain their own text undo/redo; mouse navigation also leaves graphs unchanged while a text field, dialog or popup menu is active. Choose a time-range preset to return directly to a broader view.
- **Characters:** only characters with incoming or outgoing damage records in the selected time window appear in the filters, ship groups, plots and totals. Incoming-only, outgoing-only and zero-damage hits all count as data. Search narrows these options without changing which characters are plotted. **All** / **None** applies to characters with data in this window. Characters outside the window retain their selection state when you change the range or use undo/redo. Empty ranges show an explanatory message.
- **Time range:** the default is the latest UTC day with recorded damage. Relative presets include the last **30 seconds**, **1 minute**, **5 minutes**, **10 minutes**, **30 minutes**, **hour**, **24 hours** and **7 days**. They end at the latest recorded damage, so historical logs work immediately. **All history** covers the archive.
- **Custom range:** edit the start/end fields and choose **Apply UTC range**. Accepts `YYYY-MM-DD`, `YYYY-MM-DD HH:MM` or `YYYY-MM-DD HH:MM:SS`. The end is exclusive; use the next day's date to include a whole day.
- **Graph interval:** damage in a bucket divided by that bucket's duration. Auto uses up to 1,200 buckets. Very broad ranges increase even a manually requested interval to stay within that limit; the actual interval is displayed.
- **Format options:** open the dropdown above the graphs to choose **Linear** or **Logarithmic (DPS + 1)** and **Per character**, **By ship type (ship history)** or **By ship class (ship history)**. Both graphs update together. Logarithmic mode uses `log(1 + DPS)` to preserve zero-DPS periods; axis labels, hover readings and totals remain in actual DPS/damage units. Ship grouping assigns each damage event to the hull or class observed at its UTC timestamp, then sums the selected characters, matching the sidebar grouping control. A character can contribute to several groups after changing ships. Events without recorded coverage stay under **Unknown ship** or **Unknown ship class**. Hover counts show distinct selected contributors in that bucket; counts greater than one appear in parentheses, such as **Destroyer (12)**. Class grouping combines different hulls in the same ESI group, such as Supercarrier, Titan, Cruiser or Strategic Cruiser. These choices survive refreshes and range undo/redo for the current session.
- **10-second DPS average:** toggle this checkable option in **Format options** to replace bucket DPS with a trailing average on both graphs. Each second includes its own damage and the preceding nine seconds, divided by ten, including idle seconds. Available damage just before the selected range is included in the lookback. Coarser graph intervals display the mean of those rolling rates within each bucket, including partial final buckets. It works with character/ship grouping and either scale; hover values identify the average and show fractional DPS. Damage totals, hit counts and character eligibility stay based on the original selected range. Toggle it off to restore bucket DPS. The option survives refreshes and range undo/redo for the current session.
- **Move through time:** narrow arrow buttons beside each graph shift both graphs backward or forward by 25% of the current window without changing its width. Steps round to the nearest whole second, with a one-second minimum. Each click switches to a custom UTC range, updates filters and totals, and joins the same undo/redo history as drag selections. Use **Ctrl+Z / Ctrl+Y** or Windows mouse **Back / Forward** to undo or redo a move. You can pan into empty ranges and return using the arrows or undo.
- **Wheel zoom:** scroll over the plotted area to zoom both graphs around the time beneath the pointer. Wheel up zooms in; wheel down zooms out. The time under the mouse stays at the same horizontal position, within whole-second rounding. To move forward through time, zoom out near the left side, move the mouse right and zoom back in; reverse the sides to move backward. Bounds use whole seconds, with a one-second minimum window. Continuous wheel events separated by at most **600 ms** form one undo/redo action, restoring the range before the gesture or its final range. A longer pause, pan, drag selection, undo or redo starts a separate action. Keyboard shortcuts and Windows mouse Back/Forward use this same grouped history. Filters, UTC fields and damage totals follow the new window; scale, grouping and averaging options are retained.
- **Damage totals:** damage, hit counts and average DPS for all characters or ship groups in the date range, regardless of graph selection. Average DPS includes idle time in the entire selected range. Click any column heading to sort; click it again to reverse the order. An arrow marks the active column and direction. Text columns start alphabetically; numeric columns start highest first. Damage and DPS sort by their underlying numeric values, and **Hits out / in** sorts by outgoing hits, then incoming hits. The **Members** column sorts by member count in ship-type or class mode. Headings stay visible while scrolling, and sorting survives refreshes, grouping changes and graph range navigation for the current session.
- **Group / legend:** switch between **Characters**, **Ship history** and **Ship class history**. Ship modes combine selected characters with the same ship type or class into one DPS series. The sidebar lists members under each hull or class; **Select** adds an entire group to your selection. Search matches character, historical hull and class names in class mode. A character may appear under several historical groups; selecting them in any group selects all their damage. Totals use the same grouping and include all members in the date range, regardless of graph selection.

English EVE numeric `from` / `to` combat messages are supported, including their formatting tags and UTF-8 or BOM-marked UTF-16 exports. Misses, repairs and capacitor warfare are excluded. Identical duplicate file exports are counted once; overlapping files with different content are separate sessions. Damage exchanged between two of your own characters correctly appears as outgoing for the attacker and incoming for the recipient. Files without a Listener header cannot be assigned to a character and are reported separately. Unreadable files are reported beside the log refresh controls and retried on refresh.

## Current ships through ESI

1. Open **Settings → ESI configuration…** from the menu bar. The **Application** tab contains the authentication method, public Client ID, masked client-secret field, callback port, and a live callback URL preview with a copy button. The same dialog is available through **Configure ESI…** in the **ESI & ships** tab.
2. Follow **Open EVE developer applications** and register your EVE application. Enable `esi-location.read_ship_type.v1`. Register the exact URL shown in the dialog: **`http://localhost:8080/callback`** by default. The port is configurable from 1 to 65535; the hostname stays `localhost`. Select **Native / desktop (PKCE)** for the desktop flow, or **Client ID + secret** for the standard confidential authorization-code flow and enter your application's secret. Choose **Save application configuration**.
3. In **Character tokens**, choose **Sign in with EVE Online**, select a character in the browser and grant current-ship access. Repeat for each character. Log characters match sign-ins by name, ignoring capitalization.
4. Switch the sidebar grouping to **Ship history** or **Ship class history**. Graphs sum selected members' damage, and the totals tab shows one row per hull or class with a member count. The same options are available in the graphs' **Format options** menu.

Ships refresh every 30 seconds while enabled, or when you choose **Refresh ships**. Hull names and class IDs come from ESI's public universe type endpoint; class names come from its public universe group endpoint. Hull and class lookups are cached for the session. Sign-ins renew automatically, including rotating refresh tokens. HTTP 401 triggers one renewal/retry; ESI rate limits pause further requests. Failed polls and gaps over 90 seconds break observation coverage; damage in uncovered times appears under **Unknown ship** or **Unknown ship class**. Older confirmed periods remain usable after a connection becomes stale or is removed. A failed class lookup leaves the confirmed hull available, reports the issue in ESI status and retries on the next ship refresh. Missing class data stays under **Unknown ship class**. **Disconnect** removes the locally saved sign-in; revoke the application's grant in EVE account management if you also want to revoke server-side access.

Scope validation requires the granted token scopes to include `esi-location.read_ship_type.v1`. Additional scopes are accepted, in any order, including `esi-location.read_location.v1` and `esi-location.read_online.v1`. Evela requests only the minimum ship scope during sign-in; an application may have additional scopes enabled. The same validation applies to both authentication modes, token renewal and imported tokens.

The **Character tokens** tab also supports importing existing access and/or refresh tokens issued for the configured Client ID with the ship scope. **Validate and import tokens** identifies the character from a validated access token, or obtains an access token when only a refresh token is supplied. A supplied pair is checked against the same character, and rotated refresh tokens are saved. Import replaces that character's saved tokens. Access-only imports work until expiry and then need another import or sign-in. Entries are masked and cleared after queuing an import or closing the dialog. Saved connections show token expiry and whether automatic renewal is available, with a **Disconnect** action; saved token values are not displayed.

The authentication method, Client ID, optional client secret and callback port persist across restarts. Older settings use PKCE, and older settings without a port adopt 8080. If you previously registered the old port, either update the callback registration in EVE or set that port in the dialog. Changing the callback port keeps existing character tokens; changing the Client ID requires disconnecting them first.

**Client ID + secret** authenticates both authorization-code exchanges and refresh-token requests to EVE SSO with HTTP Basic authentication. This includes refresh-token imports. The secret is sent only to the discovered SSO token endpoint and is excluded from browser URLs, public ESI queries and form bodies. **Native / desktop (PKCE)** uses a generated code verifier instead and stores no client secret. Switching to PKCE clears any saved application secret.

Grouping uses **recorded ship history at each damage event**, including when a character changes ships inside a graph bucket. Refreshing current ships never assigns the new hull to older damage. Evela cannot recover ship history from before it began recording observations. ESI cannot expose this private data for characters that have not authorized the application. Queries send ESI access tokens and character IDs to CCP; combat logs are never uploaded.

On Windows, client settings, application secrets and tokens are stored in `%APPDATA%\Evela\esi.dat`, encrypted with Windows DPAPI for the current user. The file is updated atomically and contains no plaintext secrets or tokens. Persistent ESI connections currently require Windows; log analysis remains portable. Sign-in uses a temporary listener bound only to IPv4 loopback (`127.0.0.1`) on the configured port, and advertises `http://localhost:<port>/callback`, with OAuth state validation and PKCE when selected. Access tokens are checked against EVE's published RSA/ECDSA keys, issuer, audience, expiry and requested scope.

Reference: [EVE SSO documentation](https://developers.eveonline.com/docs/services/sso/), [ESI overview](https://developers.eveonline.com/docs/services/esi/overview/).

### Ship observation history

Evela saves timestamped ship observations during ship refreshes and uses them to group damage graphs and totals. Open **ESI & ships → Ship history…** to inspect a snapshot of recorded periods, newest first. Each period includes character ID/name, ship item ID, hull type ID/name, ship class ID/name when available, ship name, first/last observed UTC timestamps and observation count. The viewer shows unresolved hulls by type ID; older sightings without an item ID show **Unknown**.

Consecutive successful sightings of the same character and ship are combined into a compact period. A ship item, hull, name or character-name change starts another period. Failed queries, gaps over 90 seconds, reconnecting and restarting also start new periods. A successful ship query is retained even if the separate public hull-name lookup fails. The stored times are observations of ESI responses, not exact boarding or unboarding times; polling and API caching limit the available evidence.

History is saved atomically with the encrypted settings in `%APPDATA%\Evela\esi.dat`, and survives restarts, token replacement and disconnecting characters. Disconnect removes the saved sign-in while retaining ship history. Upgrading preserves an older saved last-known ship as a single sighting at its original check timestamp; it does not infer any earlier coverage. There is no automatic history expiry.

The timestamp lookup supports character IDs or case-insensitive log character names. It only matches timestamps inside an observed period; times before the first sighting, after the last sighting, between different ships or across gaps remain unknown. Ambiguous names remain unknown. Historical attribution happens before bucketing or averaging, so rolling damage stays with the ship that generated it. Older periods missing hull/class metadata are resolved through public ESI lookups by their saved type ID, without changing their observed times. This also works for disconnected characters; use **Refresh ships** to retry missing metadata.

## Build and verify

Requires Go 1.23+ and Fyne's desktop build prerequisites (a C compiler; MinGW GCC on Windows).

```powershell
go test ./...
go build -ldflags="-H=windowsgui" -o evela.exe .
```

The tests use local mock SSO/ESI servers and fake credentials to verify login, token validation/renewal, encryption, ship changes, rate limits and grouping. DPAPI tests require access to the Windows user's encryption profile; restricted sandboxes may require running the tests outside that sandbox.

An optional read-only integration test checks a real archive:

```powershell
$env:EVELA_TEST_LOGS = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'EVE\logs\gamelogs'
go test -run TestLocalLogs -v
```
