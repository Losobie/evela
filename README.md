# Evela

A native Go/Fyne desktop analyzer for EVE Online game logs. It reads every character from the logs' `Listener` headers and graphs incoming and outgoing damage separately, with a consistent color per character.

## Run

Open `evela.exe`, or run the project with:

```powershell
go run .
```

The default folder is your Windows Documents known folder (including redirected/OneDrive Documents), under `EVE\logs\gamelogs`. Open **Settings → Log loading…** to configure **Log folders**, one path per line. Use **Add folder…** to append a folder with the picker, or type a local path, mapped drive, or UNC share such as `\\fleet-pc\eve-logs\gamelogs`. Include both your local folder and another computer's shared folder to analyze their logs together. Edit or delete a line to change or remove a folder. **Save and refresh** saves the complete list and loading limit and refreshes immediately; **Cancel** discards edits. The folder list is restored on the next launch. Windows must already grant your user read access to network shares. Evela only reads the configured log folders; logs are never modified or uploaded.

**Settings → Log loading…** controls how old a log file may be loaded. The default is **30 days**, measured from the current EVE time date. The inclusive cutoff uses the first eight digits and underscore in each filename: `20261018_025902_2123143905.txt` is October 18, 2026. For example, on October 18 the default includes files dated September 18 or later, including all newer dates. This filter uses neither file modification times nor timestamps inside a file. Files older than the cutoff and files without a valid `YYYYMMDD_` prefix are skipped before being opened or parsed. Choose another number of days or **Load all log files** to include an older archive or renamed files. **Save and refresh** saves the preference for future launches and queues an immediate reload, even with automatic refresh disabled. The graph's **All history** preset covers the loaded files; it does not override the loading limit. No log files are deleted.

The first import scans eligible `.txt` logs in every configured folder concurrently. A large archive may take a little time; a progress indicator shows the import. Later refreshes use an in-memory cache and only reparse changed or new files. Files that age out or are excluded by a narrower loading limit are also removed from the cache. **Auto refresh** checks all configured folders every ten seconds and advances the cutoff with the current date. Each folder has its own cache. Identical duplicate exports are counted once across all folders, while different logs with the same filename remain independent. If a share is unavailable, its last successfully loaded data remains in the combined analysis and Details identifies the affected path. The age limit still applies to retained data. A slow scan gets up to 15 seconds initially, then continues in the background while other folders keep refreshing; only one scan per folder runs at a time. Failed folders are retried, and removing a folder immediately removes its damage from the loaded analysis. Refresh details report the loaded count and files skipped for age or unrecognized filename dates. The progress indicator stays in the header without shifting the graphs. **Details…**, beside **Refresh logs**, opens refresh messages, loaded/skipped counts, and every file or folder warning. ESI refresh messages also keep a stable height and have a details dialog. Refreshes preserve character, ship and token list scroll positions. The cache lasts until you close the app.

## Use

- **Window placement:** on Windows, closing Evela saves its window size, position and maximized state as user preferences. The next launch restores them. Minimized windows reopen visibly, and Windows adjusts placements that would be off-screen after a monitor change.
- **Events:** the tab between **Totals** and **ESI & ships** lists timestamped messages from the selected loaded character logs in the current time range, including combat, notifications, movement and other non-damage events. Columns show the EVE time timestamp, the character from the log's Listener header, and the remaining message, including its channel, with client formatting tags removed and text entities decoded. Click **Timestamp** to switch between oldest-first and newest-first order. **Message search** searches only the message column and ignores case in plain-text mode. Check **Regex** to use regular expressions; regex matching is case sensitive unless the pattern includes `(?i)`. Invalid patterns show an error and no results until corrected. The Regex checkbox is saved across restarts. Search and sort remain in place during log refreshes and range navigation. The tab follows the time range and the shared **Characters** and **Character Group** filters. Selected groups combine with OR and intersect the Characters selection; overlapping groups do not duplicate rows. Characters with only non-damage messages also appear in the Characters dropdown. Ship, system, NPC and graph grouping choices do not filter Events. Select a row to read or copy its full message. Identical duplicate file exports are included once, following the log loader's existing rules; repeated events within or across distinct logs remain separate rows.
- **Incoming NPC filters:** add **NPC Names** or **NPC Types** from incoming damage’s **Add filter** menu. They provide search, **All**, and individual checkboxes. Names come from the attacker text in each damage message, matched against the bundled CCP Static Data Export. Types are CCP's NPC **groups**, such as **Sentry Gun**, **Irregular Frigate**, or **Asteroid Sansha's Nation Battleship**; they are not inferred from words in a name or from a player ship hull. **Other / unresolved** includes player-owned attackers and names absent from the lookup. Defaults include all damage. Selections within a filter use OR; name/type filters intersect each other and the global filters. Changes affect incoming damage, hit counts, averages, totals and the summary; outgoing damage and structure markers retain the global filters. Choices persist across restarts and range navigation. Options reflect incoming hits in the time window, including zero-damage hits. Filtering occurs before per-second totals, bucketing, averaging and ship grouping, so simultaneous hits from different sources remain separable.
- **Global and graph filters:** use **Add filter** in the bar above the graphs or in any graph card to show a filter. The dropdown lists every available filter with a checkbox; checking or unchecking filters keeps it open until you click away. Add filter stays on the left and Group By on the right; active filters share their row and wrap when needed. The × button removes it and immediately stops applying its selections; adding it again restores those selections. New installations start without visible filters; existing restrictions migrate as visible filters. Global filters intersect every graph, damage Totals, markers and the summary. Graph filters affect only their graph (damage filters also update the matching direction in Totals and the summary). Each dropdown provides search, **All**, and individual checkboxes. Choices within one filter use OR; visible filters use AND. Visibility and selections persist separately for each scope. Character sidebar selections appear as a visible global Characters filter. Ship/class and system filters use history at event time, including the 45-second last-observed allowance; unknown coverage remains selectable.
- **Available filters:** Characters, Character Group, Ship Type, Ship Class, and System are available globally and on every graph. Both damage graphs additionally offer Weapon Type and Weapon Strength. Incoming damage adds Attacker, Attacker Ship, NPC Names and NPC Types. Logistics adds Type (Shield, Armor, Capacitor); E-War adds Effect Type; mining adds Ore Name, Ore Type and Message Type. Options in graph filters come from records for that graph in the selected time window.
- **Named character groups:** open **Settings → Character groups…**. Choose **New group…**, enter a name, and use the two lists to set membership. The left list contains characters with any timestamped log entry in the current time window, including non-damage notifications, plus characters removed during this settings session. The right list contains every current member, including characters outside the time window or no longer present in the loaded logs. Use **Ctrl-click** to toggle individual characters or **Shift-click** to select a range in either list, then use **Add → / ← Remove** to transfer the selection. Double-click a character to transfer it individually. The left list follows time-window/data refreshes; removed characters remain available until you close the panel. **Save group** applies and saves the name and members. Choose an existing group to edit it, or **Delete group** to remove it. Save before switching drafts; closing discards unsaved edits.
- **Character group filters:** the grouping dropdown includes **Character groups**, which combines selected active members into one series per named group and shows unmatched characters under **Ungrouped characters**. Each saved group also appears as **Group: name**, which filters the graphs, legend, totals and summary to that group's members. **Group By** offers **Character Group**; choose individual groups with the separate **Character Group** filter. Groups can overlap: shared characters contribute to each group row/series, while the summary counts each selected character once. Membership is matched without case sensitivity. Grouped totals include the filtered active members; the legend, hover counts, averaging and column sorting work with named groups. Saved groups and the selected grouping/filter are restored on the next launch. Renaming a selected group retains its filter; deleting it returns to per-character mode.
- **Structure invulnerability markers:** enable **Options → Target invulnerability indicators** to show markers. This option defaults to off and is saved automatically for the next launch. When enabled, the outgoing graph shows a vertical red line at a **Target is invulnerable.** notification when that character last hit a recognized player structure within the preceding **30 seconds**. Identification uses the target's parenthesized type, including Metenox Moon Drills, Upwell citadels, engineering complexes, refineries, navigation structures, skyhooks and sovereignty structures. Legacy control towers and customs offices also require a corporation ticker beside the target name. Ships, NPC hulls and unrecognized targets do not qualify; switching outgoing damage to one of them clears the structure context. Repeated warnings produce one marker until another structure hit. Markers follow the selected characters and time range, with identical reports from multiple characters merged. Hover near a line to see its exact EVE time time and structure name. Markers stay at their original event times with averaging or ship-history grouping, and do not add damage or hits to totals. The timeline includes qualifying notifications after the final damage hit, so relative ranges can show them. Supported modern structure families follow [CCP's Upwell overview](https://support.eveonline.com/hc/en-us/articles/213021829-Upwell-Structures) and [sovereignty structure documentation](https://www.eveonline.com/news/view/sovereignty-structures-and-transition).
- **Graphs:** separate incoming and outgoing timelines for all selected characters. With the 10-second average enabled, colored lines show DPS and hover displays a bucket's three highest rates. With averaging off, each logged damage hit is a separate colored point at its recorded second and damage amount. Hits in the same second remain separate; idle time adds no points or connecting lines. Hover near a hit timestamp to inspect up to three individual hit amounts, labeled with the group and contributing character. Zero-damage hits appear on the baseline. Colors follow the selected grouping in either display mode. The EVE time timestamp stays neutral, and long readouts are clipped within the graph header. Drag horizontally inside any plot to highlight a time range, in either direction, then release to zoom all five graphs and the damage totals into that range. Selection updates the EVE time fields and switches to **Custom**, so refreshes retain it. Ranges include the selected seconds; tiny movements and ordinary clicks do not zoom. **Ctrl+Z** undoes a graph range change; **Ctrl+Y** reapplies an undone change. On Windows, mouse **Back** and **Forward** do the same undo/redo within the Evela window, using the same history as the keyboard shortcuts. Multiple selections can be undone/redone in order, restoring all five graphs, totals, EVE time fields and the previous preset. New drag selections discard the redo branch. Refreshes preserve history; manually editing dates, choosing another preset or loading another log folder starts new history. Text fields retain their own text undo/redo; mouse navigation also leaves graphs unchanged while a text field, dialog or popup menu is active. Choose a time-range preset to return directly to a broader view.
- **Characters:** the **Characters** filter lists characters with damage, logistics, incoming E-War or mining records in the selected time window, including incoming-only, outgoing-only, and zero-damage hits. Search narrows the checkbox options without changing the data. **All** selects or clears every option, including search-hidden options. Selections outside the current time window are retained when the range changes.
- **Time range:** the default is the last **30 minutes**. Relative presets include the last **10 minutes**, **30 minutes**, **hour**, **24 hours** and **7 days**. They end at the latest recorded damage, logistics, E-War, mining event or structure marker, so historical logs work immediately. **All history** covers the archive. The selected preset is saved across restarts and continues following the loaded logs. Applied custom ranges, including graph zooms and pans, restore their exact EVE time bounds.
- **Custom range:** use the calendar buttons in the start/end fields to pick a date and 24-hour time (including seconds). Valid changes immediately update graphs and totals; there is no Apply button. You can also type `YYYY-MM-DD`, `YYYY-MM-DD HH:MM` or `YYYY-MM-DD HH:MM:SS`. The end is exclusive; use the next day's date to include a whole day.
- **Graph interval:** controls the buckets used for averaged DPS lines. Auto uses up to 1,200 buckets. Very broad ranges increase even a manually requested interval to stay within that limit. Individual-hit points retain their original timestamps and damage amounts at every interval.
- **Group By:** every graph independently offers Character, Character Group, historical ship type/class, and System. Outgoing damage also offers Weapon Type and Weapon Strength, and controls the grouping of Totals. Incoming damage also offers those weapon choices plus Attacker, Ship (attacker hull), NPC, and NPC Type. Logistics and E-War offer Type (assistance or effect type). Mining offers Ore Name and Ore Type; its message kinds always remain separate, so it has no redundant Message Type grouping. Historical grouping uses the log character at event time. Overlapping character groups can duplicate records between groups. Grouping choices persist separately.
- **DPS averages:** shared **Options** offers **10-second DPS average** and **30-second DPS average**. The choices are mutually exclusive; selecting the active choice again turns averaging off. Ten seconds remains the default, and saved on/off choices from earlier versions are retained. Both windows apply to every graph and grouping mode: damage uses DPS, logistics uses HP/s or GJ/s, E-War uses events/s or GJ/s, and mining uses units/s. Each rolling rate divides the events in its trailing window by the full 10 or 30 seconds, including idle seconds and available events before the selected range. Coarse graph intervals display the mean of those rates within each bucket, including partial final buckets. Hover identifies the chosen window and fractional rate. Totals, hit counts and character eligibility stay based on the original selected range. Turning averaging off shows individual events at their original amounts. The choice is saved automatically and survives restarts, refreshes and range undo/redo.
- **Move through time:** narrow arrow buttons beside each graph shift all five graphs backward or forward by 25% of the current window without changing its width. Steps round to the nearest whole second, with a one-second minimum. Each click switches to a custom EVE time range, updates filters and totals, and joins the same undo/redo history as drag selections. Use **Ctrl+Z / Ctrl+Y** or Windows mouse **Back / Forward** to undo or redo a move. You can pan into empty ranges and return using the arrows or undo.
- **Wheel zoom:** scroll over the plotted area to zoom all five graphs around the time beneath the pointer. Wheel up zooms in; wheel down zooms out. The time under the mouse stays at the same horizontal position, within whole-second rounding. To move forward through time, zoom out near the left side, move the mouse right and zoom back in; reverse the sides to move backward. Bounds use whole seconds, with a one-second minimum window. Continuous wheel events separated by at most **600 ms** form one undo/redo action, restoring the range before the gesture or its final range. A longer pause, pan, drag selection, undo or redo starts a separate action. Keyboard shortcuts and Windows mouse Back/Forward use this same grouped history. Filters, EVE time fields and damage totals follow the new window; scale, grouping and averaging options are retained.
- **Totals:** damage, hit counts and average DPS for characters or ship groups in the date range, after applying the current filters. Average DPS includes idle time in the entire selected range. Click any column heading to sort; click it again to reverse the order. An arrow marks the active column and direction. Text columns start alphabetically; numeric columns start highest first. Damage and DPS sort by their underlying numeric values, and **Hits out / in** sorts by outgoing hits, then incoming hits. The **Members** column sorts by member count in ship-type or class mode. Headings stay visible while scrolling, and sorting survives refreshes, grouping changes and graph range navigation for the current session.
- **Logistics graphs:** **Outgoing logistics** sits directly below **Outgoing**; **Incoming logistics** sits directly below **Incoming**. Each has its own **Type** checkbox dropdown with **All** at the top, plus **Shield**, **Armor** and **Capacitor**. Select any combination; All includes search-hidden options, and clearing All shows none. Type choices persist independently. New users start with all three selected; existing exclusive repair/capacitor choices are migrated. The plot uses HP for repairs and GJ for capacitor transfers. When both are selected, the left axis shows HP and the right axis shows GJ; unlike units are never added together, including when grouping by character or ship. With either shared DPS average enabled, axes and hover use **HP/s** and **GJ/s**, including lookback; otherwise each logged transfer appears at its original amount and timestamp, including zero-value events. Hover identifies the log character, original message and correct unit; full messages remain in Events. Remote armor repaired, shield boosted and capacitor transmitted messages are recognized: to is outgoing; by or from is incoming. [Published combat-log examples](https://forums.eveonline.com/t/opportunity-system-logistics-readouts-armor-cap-shield-implementation/412775). Local repairers, shield boosters, capacitor boosters, Nosferatu and neutralizers are excluded. Shared character, ship, group and system filters apply at event time; NPC damage filters do not change logistics. Logistics-only characters appear in Characters and the selected count; damage totals and E-War retain their own records.
- **Mining graph:** enable **Options → Show Mining**; it starts hidden. **Ore Name** keeps exact grades such as Bountiful Xenotime and Prismatic Gneiss separate. **Ore Type** uses embedded CCP static-data groups, such as **Exceptional Moon Ore**, **Ubiquitous Moon Ore** and **Gneiss**. Unknown names remain selectable as **Unknown ore type**; historical grades missing from the SDE can match a known ore-name suffix. **Message Type** offers **Ore mined**, **Compressed** and **Waste**. Each filter supports search, checkboxes and All, and its choices persist. All three message types are initially selected and are always separate series, so mined, compressed and wasted units are not added together. Mining messages supply mined units and lost residue (waste), including zero residue. Successful compression notifications use the reported output quantity and the original ore grade for filtering. **Group By** independently offers **Character**, **Character Group**, **Ship type (ship history)** and **Ore Type**, with saved choices and overlapping group membership support. Ship type uses the hull recorded at each event timestamp, including averaging lookback; missing history stays **Unknown ship**. Ore Type combines ore grades and characters within the same static-data category, while keeping mined, compressed and waste series separate. Shared character, group, ship and system filters apply; NPC damage filters do not affect mining. The shared averaging option shows units/s with the selected 10- or 30-second lookback; disabling it shows each original amount in units. Hover includes the character and original message. Mining-only logs work with the archive time presets and Characters filter without adding damage totals.
- **Graph visibility:** **Options** has independent **Show Outgoing damage**, **Show Outgoing logistics**, **Show Incoming damage**, **Show Incoming logistics**, **Show Incoming E-War**, and **Show Mining** toggles. Without a saved visibility preference, only Outgoing damage and Incoming damage are shown; both logistics graphs, Incoming E-War and Mining start hidden. Explicit saved show/hide choices override these defaults independently for each graph. The Options dropdown stays open while toggling graph visibility and updates checkmarks immediately; click outside or press Escape to close it. Hidden graphs collapse out of the panel; their data, filters, metrics, totals and time range continue updating. Each choice is saved across restarts. Hiding every graph leaves a message in the panel; Options stays available to show graphs again.
- **Scrolling graphs:** the graph panel scrolls vertically in this order: Outgoing, Outgoing logistics, Incoming, Incoming logistics, Incoming E-War, Mining. Use the right scrollbar or the mouse wheel over graph headings to scroll. The time controls and shared filters stay visible. Wheel movement over a plot keeps its existing zoom behavior; zoom, drag selection, pan and undo/redo synchronize all six graphs. Refreshes, metric changes and time-range navigation retain the panel scroll position.
- **Incoming E-War:** this graph groups logged incoming effects by type. Choose **Effect events** to count notifications, or **Capacitor drained (GJ)** for neutralizer and Nosferatu amounts. Either shared DPS average shows trailing-average **events/s** or **GJ/s** here; turning it off shows individual event points or GJ amounts, including zero-drain events. Hover over individual points for the receiving character and original message; the Events tab retains full messages. Neutralizer losses and negative Nosferatu `energy drained to` messages are included; capacitor gains and outgoing effects are excluded. Incoming warp scramble/disruption attempts are counted as notifications, without assuming success. Explicit incoming notifications for stasis webifiers, target painters, turret/tracking or missile/guidance disruption, sensor dampening and ECM are recognized when present. EVE does not consistently write these effects to game logs: unreported effects, durations and strengths cannot be reconstructed; an empty graph does not establish absence of E-War. [Firsthand log-coverage report](https://forums.eveonline.com/t/capsuleer-agression-without-log-entry/506006). Shared character, group, ship and system filters apply at event time; the incoming damage NPC filters and the Group By menus for other graphs do not change this graph. Its own Group By controls how events are combined. Its time range, zoom, pan and undo/redo follow the other graphs. The metric choice persists. E-War-only characters appear in Characters and contribute to the selected count and E-War footer summary, while damage totals remain based on damage records.
- **Incoming Group By:** the dropdown above the incoming plot is independent of outgoing grouping and Totals. **Character** groups by the receiving log character; **Character Group** combines receiving characters using saved groups (overlapping membership can appear in multiple groups). **Attacker** uses the logged attacker/corporation/hull combination; logs do not provide a unique ship item ID or custom ship name, so same-pilot, same-corporation, same-hull ships are combined. **Ship** combines sources with the same logged hull. **NPC** uses matched NPC names; **NPC Type** uses CCP NPC groups. Sources missing the attribute for a chosen mode stay under **Other / unresolved**. Recognized structures are not treated as pilots. All shared and NPC filters apply before source grouping, bucketing and rolling averages. Averaged hover member counts refer to selected receiving characters; individual-hit hover identifies the receiving character. The incoming choice defaults to **Character**, is saved separately, and survives refreshes and range navigation.

**Weapon Type and Weapon Strength:** each damage graph has independent filters under **Add filter**, applied before grouping or averaging. Weapon Type uses the logged weapon or drone name (for example, **Ogre I** or **Heavy Beam Laser II**). Weapon Strength uses the logged hit quality, including **Hits**, **Penetrates**, **Smashes**, and **Misses**. Both damage graphs offer these Group By choices; outgoing grouping also applies to Totals. Missing attributes appear as **Unknown weapon type** or **Unknown weapon strength**. Misses remain zero-damage records and do not increase landed-hit counts. These filters do not affect logistics, mining, or E-War.

English EVE numeric `from` / `to` combat messages are supported, including their formatting tags and UTF-8 or BOM-marked UTF-16 exports. Misses and repairs are excluded from damage; remote repairs and capacitor transfers appear in the logistics graphs, and incoming capacitor warfare appears in Incoming E-War. Identical duplicate file exports are counted once; overlapping files with different content are separate sessions. Damage exchanged between two of your own characters correctly appears as outgoing for the attacker and incoming for the recipient. Files without a Listener header cannot be assigned to a character and are reported separately. Unreadable files are reported beside the log refresh controls and retried on refresh.

## Current ships through ESI

1. Open **Settings → ESI configuration…** from the menu bar. The **Application** tab contains the public Client ID, callback port, and a live callback URL preview with a copy button. The Client ID defaults to `b680ade5175c4385a1e800b4bedb70bb`. The same dialog is available through **Configure ESI…** in the **ESI & ships** tab.
2. Sign-in uses **PKCE**. To use your own application, follow **Open EVE developer applications**, register a native / desktop application, and enable `esi-location.read_ship_type.v1` and `esi-location.read_location.v1`. Register the exact URL shown in the dialog: **`http://localhost:8080/callback`** by default. The port is configurable from 1 to 65535; the hostname stays `localhost`. Enter the public Client ID and choose **Save application configuration**.
3. In **Character tokens**, choose **Sign in with EVE Online**, select a character in the browser and grant ship and location access. Repeat for each character. Log characters match sign-ins by name, ignoring capitalization.
4. Switch the sidebar grouping to **Ship history** or **Ship class history**. The outgoing graph sums selected members' damage, and the totals tab shows one row per hull or class with a member count. The same options are available in the graphs' **Format options** menu.

Ships and locations refresh every 30 seconds while enabled, or when you choose **Refresh ships & locations**. Hull names and class IDs come from ESI's public universe type endpoint; class names come from its public universe group endpoint. Hull and class lookups are cached for the session. Sign-ins renew automatically, including rotating refresh tokens. HTTP 401 triggers one renewal/retry; ESI rate limits pause further requests. Failed polls and gaps over 90 seconds break observed periods. The last observed ship is assumed for up to **45 seconds** after its last sighting, unless a newer ship is observed first; damage outside that coverage appears under **Unknown ship** or **Unknown ship class**. Older confirmed periods remain usable after a connection becomes stale or is removed. A failed class lookup leaves the confirmed hull available, reports the issue in ESI status and retries on the next ship refresh. Missing class data stays under **Unknown ship class**. **Disconnect** removes the locally saved sign-in; revoke the application's grant in EVE account management if you also want to revoke server-side access.

Sign-in requests `esi-location.read_ship_type.v1` and `esi-location.read_location.v1`. Enable both scopes in your EVE application. Existing ship-only tokens remain usable for ship tracking; sign in again to grant location access. Tokens that already grant location access are recognized automatically. Scope validation requires the ship scope and accepts additional grants in any order. The same validation applies to sign-in and token renewal.

The **Character tokens** tab uses **Sign in with EVE Online** to connect each character. Access and refresh tokens arrive through this authorization flow and renew automatically. Saved connections show token expiry and whether automatic renewal is available, with a **Disconnect** action; saved token values are not displayed.

Background ship and location refreshes do not block sign-in. Only one browser sign-in is active at a time; **Cancel sign-in** releases the callback listener so you can try again. Completed sign-ins are saved alongside existing characters and history before their ships and locations are refreshed.

The Client ID and callback port persist across restarts. Existing saved Client IDs are retained; missing IDs adopt the default above, and older settings without a port adopt 8080. Changing the callback port keeps existing character tokens; changing the Client ID requires disconnecting them first. Former client-secret configurations must use a PKCE application and may require signing in again. Legacy client-secret fields are ignored and omitted when settings are next saved.

Outgoing ship grouping uses **recorded ship history at each damage event**, including when a character changes ships inside a graph bucket. Refreshing current ships never assigns the new hull to older damage. Evela cannot recover ship history from before it began recording observations. ESI cannot expose this private data for characters that have not authorized the application. Queries send ESI access tokens and character IDs to CCP; combat logs are never uploaded.

On Windows, client settings and tokens are stored in `%APPDATA%\Evela\esi.dat`, encrypted with Windows DPAPI for the current user. The file is updated atomically and contains no plaintext tokens. Persistent ESI connections currently require Windows; log analysis remains portable. Sign-in uses a temporary listener bound only to IPv4 loopback (`127.0.0.1`) on the configured port, and advertises `http://localhost:<port>/callback`, with OAuth state validation and PKCE. Access tokens are checked against EVE's published RSA/ECDSA keys, issuer, audience, expiry and requested scope.

Reference: [EVE SSO documentation](https://developers.eveonline.com/docs/services/sso/), [ESI overview](https://developers.eveonline.com/docs/services/esi/overview/).

### Ship observation history

Evela saves timestamped ship observations during ship refreshes and uses them to group damage graphs and totals. Open **ESI & ships → Ship history…** to inspect a snapshot of recorded periods, newest first. Each period includes character ID/name, ship item ID, hull type ID/name, ship class ID/name when available, ship name, first/last observed EVE time timestamps and observation count. The viewer shows unresolved hulls by type ID; older sightings without an item ID show **Unknown**.

Consecutive successful sightings of the same character and ship are combined into a compact period. A ship item, hull, name or character-name change starts another period. Failed queries, gaps over 90 seconds, reconnecting and restarting also start new periods. A successful ship query is retained even if the separate public hull-name lookup fails. The stored times are observations of ESI responses, not exact boarding or unboarding times; polling and API caching limit the available evidence.

History is saved atomically with the encrypted settings in `%APPDATA%\Evela\esi.dat`, and survives restarts, token replacement and disconnecting characters. Disconnect removes the saved sign-in while retaining ship history. Upgrading preserves an older saved last-known ship as a single sighting at its original check timestamp; it does not infer any earlier coverage. There is no automatic history expiry.

The timestamp lookup supports character IDs or case-insensitive log character names. It matches observed periods and assumes the same ship for up to 45 seconds after each period's last sighting. A newer observation takes precedence immediately. Times before the first sighting or more than 45 seconds beyond the preceding period remain unknown, as do ambiguous names. The displayed and saved observation timestamps are unchanged by this allowance. Historical attribution happens before bucketing or averaging, so rolling damage stays with the ship assigned to its original event. Older periods missing hull/class metadata are resolved through public ESI lookups by their saved type ID, without changing their observed times. This also works for disconnected characters; use **Refresh ships & locations** to retry missing metadata.

### Location observation history and System filter

Open **ESI & ships → Location history…** to inspect recorded locations, newest first, in the **Game logs** and **ESI observations** tabs. Each ESI period saves the character ID/name, solar system ID/name, station or structure ID when docked, first/last observed EVE time timestamps, and observation count. Current locations are shown alongside current ships. System names come from the public universe systems endpoint and are cached for the session; unnamed systems remain usable by ID and missing names are retried, including for disconnected characters.

ESI location history uses the same storage and timing rules as ship history: consecutive successful sightings of the same location combine, while a system, station, structure or character-name change starts a new period. Failed location queries, gaps over 90 seconds, reconnecting, token replacement and restarting also begin new periods. Ship and location queries succeed independently. A failed system-name lookup retains the confirmed location ID. History is saved atomically in the same encrypted `%APPDATA%\Evela\esi.dat` file and survives disconnects and restarts without automatic expiry.

The **System** filter supports search, **All**, individual selections and **Unknown system**, with choices saved across restarts. Selected systems combine with OR and intersect the other filter categories. Each damage event and structure marker is matched to the character's historical location at its original timestamp, before bucketing or averaging. When logs do not establish a location, the last ESI location is assumed for up to 45 seconds, until a newer observation begins. Events before tracking, outside coverage or with ambiguous character names remain unknown. Stored observation timestamps are never extended, and refreshing a current location does not assign it to earlier damage.

Game-log locations take priority over ESI, even if a newer ESI poll still reports a cached system. Supported English messages include:

- `Jumping from Mamet to Hoshoun`
- `A Conduit Field activated by Clento Loso jumps you to Mai.`
- `Activating a Conduit Field jumps you to Camal, bringing along 22 passengers.`

The destination applies from the message timestamp until the next logged movement within that session. A jump origin also identifies the system between session start and the first jump. Before a first conduit message, the previous system stays unknown unless ESI provides it. Location coverage follows the session's timestamped entries, with a 45-second allowance after its last entry; it is not carried indefinitely across offline gaps. Names, including multiword and wormhole systems, work without an ESI sign-in. Once ESI supplies a matching system ID, the filter combines both sources into one option and keeps the existing selection.

Log movement events and session bounds are saved in the same encrypted `esi.dat` history, including characters without ESI accounts. Repeated refreshes and duplicate/overlapping exports do not duplicate movement events. Growing logs extend their existing session. Saved log locations remain available after the source files fall outside the loading limit or are removed. **Game logs** shows the derived coverage intervals; **ESI observations** retains the original sampled data. Both damage graphs, totals, rolling averages and structure markers use the same preference for logs.

## NPC data source

CCP publishes the [official Static Data Export](https://developers.eveonline.com/docs/services/static-data/). The embedded `npc_data.json.gz` is generated from JSONL SDE **3607705**, released **2026-10-12**, and contains **7,418 NPC types** and **415 groups**. It joins `types.groupID` to `groups._key`, retaining groups in the **Entity** category (`categoryID = 11`). Unpublished types are included: NPCs such as Amarr Sentry Gun are marked `published: false`. All supplied name translations are indexed. EVE Online and its game data are copyright CCP hf.

Combat logs usually supply display names without type IDs. Matching uses exact names ignoring capitalization and surrounding whitespace, after removing weapon/hit-quality suffixes. Corporation/hull suffixes identify player-owned sources before NPC matching. A shared display name resolves only IDs common to every candidate; conflicting NPC groups appear as **Ambiguous NPC type**. Unmatched names stay in **Other / unresolved**, including new NPCs introduced after the bundled snapshot. No faction, hull, or NPC status is guessed for unmatched names. English combat messages remain required. Resolution is entirely local and needs no ESI sign-in or runtime download.

To update, download CCP's [latest JSONL SDE](https://developers.eveonline.com/static-data/eve-online-static-data-latest-jsonl.zip) into `.cache`, then regenerate, verify and rebuild:

```powershell
go run ./tools/npcdata -sde .cache/eve-sde-<build>-jsonl.zip
go run ./tools/oredata -sde .cache/eve-sde-<build>-jsonl.zip
go test ./...
go build -ldflags="-H=windowsgui" -o evela.exe .
Compress-Archive -LiteralPath evela.exe -DestinationPath evela.zip -Force
```

The mining lookup `ore_data.json` is generated from the same official JSONL SDE **3607705**, released **2026-10-12**, and contains **502 English ore names**. It joins types to groups in the **Asteroid** category (`categoryID = 25`), including ice and compressed variants. Moon group labels replace “Moon Asteroids” with “Moon Ore” for the filter. The embedded lookup works offline.

The generator reads build/release metadata from the archive; update the version/counts above when replacing the snapshot. Only compact names, type IDs and group names/IDs are embedded; the full archive is excluded from version control.

## Build and verify

Requires Go 1.23+ and Fyne's desktop build prerequisites (a C compiler; MinGW GCC on Windows).

```powershell
go test ./...
go build -ldflags="-H=windowsgui" -o evela.exe .
Compress-Archive -LiteralPath evela.exe -DestinationPath evela.zip -Force
```

The application and Windows executable use `icon.svg`. After changing the SVG, run `go generate .` to regenerate `icon.ico` and `icon_windows_amd64.syso`, then rebuild with the command above. Icon resource generation requires MinGW `windres`.

The tests use local mock SSO/ESI servers and fake credentials to verify login, token validation/renewal, encryption, ship changes, rate limits and grouping. DPAPI tests require access to the Windows user's encryption profile; restricted sandboxes may require running the tests outside that sandbox.

An optional read-only integration test checks a real archive:

```powershell
$env:EVELA_TEST_LOGS = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'EVE\logs\gamelogs'
go test -run TestLocalLogs -v
```
