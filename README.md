# Evela

A native Go/Fyne desktop analyzer for EVE Online game logs. It reads every character from the logs' `Listener` headers and graphs incoming and outgoing damage separately, with a consistent color per character.

## Run

Open `evela.exe`, or run the project with:

```powershell
go run .
```

The default folder is your Windows Documents known folder (including redirected/OneDrive Documents), under `EVE\logs\gamelogs`. Open **Settings → Log loading…** to configure **Log folders**, one path per line. Use **Add folder…** to append a folder with the picker, or type a local path, mapped drive, or UNC share such as `\\fleet-pc\eve-logs\gamelogs`. Include both your local folder and another computer's shared folder to analyze their logs together. Edit or delete a line to change or remove a folder. **Save and refresh** saves the complete list and loading limit and refreshes immediately; **Cancel** discards edits. The folder list is restored on the next launch. Windows must already grant your user read access to network shares. Evela only reads the configured log folders; logs are never modified or uploaded.

**Settings → Log loading…** controls how old a log file may be loaded. The default is **30 days**, measured from the current EVE time date. The inclusive cutoff uses the first eight digits and underscore in each filename: `20261018_025902_2123143905.txt` is October 18, 2026. For example, on October 18 the default includes files dated September 18 or later, including all newer dates. This filter uses neither file modification times nor timestamps inside a file. Files older than the cutoff and files without a valid `YYYYMMDD_` prefix are skipped before being opened or parsed. Choose another number of days or **Load all log files** to include an older archive or renamed files. **Save and refresh** saves the preference for future launches and queues an immediate reload, even with automatic refresh disabled. The graph's **All history** preset covers the loaded files; it does not override the loading limit. No log files are deleted.

The first import scans eligible `.txt` logs in every configured folder concurrently. A large archive may take a little time; a progress indicator shows the import. Later refreshes use an in-memory cache and only reparse changed or new files. Files that age out or are excluded by a narrower loading limit are also removed from the cache. **Auto refresh** checks all configured folders every ten seconds and advances the cutoff with the current date. Each folder has its own cache. Identical duplicate exports are counted once across all folders, while different logs with the same filename remain independent. If a share is unavailable, its last successfully loaded data remains in the combined analysis and Details identifies the affected path. The age limit still applies to retained data. A slow scan gets up to 15 seconds initially, then continues in the background while other folders keep refreshing; only one scan per folder runs at a time. Failed folders are retried, and removing a folder immediately removes its damage from the loaded analysis. Refresh details report the loaded count and files skipped for age or unrecognized filename dates. The progress indicator stays in the header without shifting the graphs. **Details…**, beside **Refresh logs**, opens refresh messages, loaded/skipped counts, and every file or folder warning. ESI refresh messages also keep a stable height and have a details dialog. Refreshes preserve character, ship and token list scroll positions. The cache lasts until you close the app.

## Use

- **Events:** the tab between **Damage totals** and **ESI & ships** lists timestamped messages from all loaded character logs in the current time range, including combat, notifications, movement and other non-damage events. Columns show the EVE time timestamp, the character from the log's Listener header, and the remaining message, including its channel, with client formatting tags removed and text entities decoded. Click **Timestamp** to switch between oldest-first and newest-first order. **Message search** searches only the message column and ignores case in plain-text mode. Check **Regex** to use regular expressions; regex matching is case sensitive unless the pattern includes `(?i)`. Invalid patterns show an error and no results until corrected. The Regex checkbox is saved across restarts. Search and sort remain in place during log refreshes and range navigation. The tab follows the time range independently of damage filters and graph grouping. Select a row to read or copy its full message. Identical duplicate file exports are included once, following the log loader's existing rules; repeated events within or across distinct logs remain separate rows.
- **Incoming NPC filters:** **NPC Names** and **NPC Types**, immediately above the incoming plot, provide search, **All**, and individual checkboxes. Names come from the attacker text in each damage message, matched against the bundled CCP Static Data Export. Types are CCP's NPC **groups**, such as **Sentry Gun**, **Irregular Frigate**, or **Asteroid Sansha's Nation Battleship**; they are not inferred from words in a name or from a player ship hull. **Other / unresolved** includes player-owned attackers and names absent from the lookup. Defaults include all damage. Selections within a filter use OR; name/type filters intersect each other and the shared filters. Changes affect incoming damage, hit counts, averages, totals and the summary; outgoing damage and structure markers retain the shared filters. Choices persist across restarts and range navigation. Options reflect incoming hits in the time window, including zero-damage hits. Filtering occurs before per-second totals, bucketing, averaging and ship grouping, so simultaneous hits from different sources remain separable.
- **Live filters:** use **Characters**, **Ship Type**, **Ship Class**, **Character Group**, and **System** beside **Group By** and **Options**. Each button opens a dropdown with a search field, an **All** checkbox, and individual checkboxes. Changes apply immediately; **All** includes options hidden by search. Choices within a category are combined with OR, and categories are combined with AND. Ship filters match the ship at each event's EVE time time, including the 45-second last-observed allowance. System filters match the recorded location at each event, with the same 45-second allowance. Unknown ship/class/system and ungrouped characters can be selected explicitly. The same filters affect both graphs, Damage totals, markers, and the summary. Choices persist across restarts.
- **Named character groups:** open **Settings → Character groups…**. Choose **New group…**, enter a name, and use the two lists to set membership. The left list contains characters with any timestamped log entry in the current time window, including non-damage notifications, plus characters removed during this settings session. The right list contains every current member, including characters outside the time window or no longer present in the loaded logs. Use **Ctrl-click** to toggle individual characters or **Shift-click** to select a range in either list, then use **Add → / ← Remove** to transfer the selection. Double-click a character to transfer it individually. The left list follows time-window/data refreshes; removed characters remain available until you close the panel. **Save group** applies and saves the name and members. Choose an existing group to edit it, or **Delete group** to remove it. Save before switching drafts; closing discards unsaved edits.
- **Character group filters:** the grouping dropdown includes **Character groups**, which combines selected active members into one series per named group and shows unmatched characters under **Ungrouped characters**. Each saved group also appears as **Group: name**, which filters the graphs, legend, totals and summary to that group's members. **Group By** offers **Character Group**; choose individual groups with the separate **Character Group** filter. Groups can overlap: shared characters contribute to each group row/series, while the summary counts each selected character once. Membership is matched without case sensitivity. Grouped totals include the filtered active members; the legend, hover counts, averaging and column sorting work with named groups. Saved groups and the selected grouping/filter are restored on the next launch. Renaming a selected group retains its filter; deleting it returns to per-character mode.
- **Structure invulnerability markers:** enable **Options → Target invulnerability indicators** to show markers. This option defaults to off and is saved automatically for the next launch. When enabled, the outgoing graph shows a vertical red line at a **Target is invulnerable.** notification when that character last hit a recognized player structure within the preceding **30 seconds**. Identification uses the target's parenthesized type, including Metenox Moon Drills, Upwell citadels, engineering complexes, refineries, navigation structures, skyhooks and sovereignty structures. Legacy control towers and customs offices also require a corporation ticker beside the target name. Ships, NPC hulls and unrecognized targets do not qualify; switching outgoing damage to one of them clears the structure context. Repeated warnings produce one marker until another structure hit. Markers follow the selected characters and time range, with identical reports from multiple characters merged. Hover near a line to see its exact EVE time time and structure name. Markers stay at their original event times with averaging or ship-history grouping, and do not add damage or hits to totals. The timeline includes qualifying notifications after the final damage hit, so relative ranges can show them. Supported modern structure families follow [CCP's Upwell overview](https://support.eveonline.com/hc/en-us/articles/213021829-Upwell-Structures) and [sovereignty structure documentation](https://www.eveonline.com/news/view/sovereignty-structures-and-transition).
- **Damage graphs:** separate incoming and outgoing DPS timelines for all selected characters. Match each line to the color beside its character. Hover to inspect a time bucket's three highest rates; each character or ship-group reading uses the same color as its plotted line. The EVE time timestamp stays neutral, and long readouts are clipped within the graph header. Drag horizontally inside either plot to highlight a time range, in either direction, then release to zoom both graphs and the damage totals into that range. Selection updates the EVE time fields and switches to **Custom**, so refreshes retain it. Ranges include the selected seconds; tiny movements and ordinary clicks do not zoom. **Ctrl+Z** undoes a graph range change; **Ctrl+Y** reapplies an undone change. On Windows, mouse **Back** and **Forward** do the same undo/redo within the Evela window, using the same history as the keyboard shortcuts. Multiple selections can be undone/redone in order, restoring both graphs, totals, EVE time fields and the previous preset. New drag selections discard the redo branch. Refreshes preserve history; manually editing dates, choosing another preset or loading another log folder starts new history. Text fields retain their own text undo/redo; mouse navigation also leaves graphs unchanged while a text field, dialog or popup menu is active. Choose a time-range preset to return directly to a broader view.
- **Characters:** the **Characters** filter lists characters with damage records in the selected time window, including incoming-only, outgoing-only, and zero-damage hits. Search narrows the checkbox options without changing the data. **All** selects or clears every option, including search-hidden options. Selections outside the current time window are retained when the range changes.
- **Time range:** the default is the last **30 minutes**. Relative presets include the last **10 minutes**, **30 minutes**, **hour**, **24 hours** and **7 days**. They end at the latest recorded damage, so historical logs work immediately. **All history** covers the archive. The selected preset is saved across restarts and continues following the loaded logs. Applied custom ranges, including graph zooms and pans, restore their exact EVE time bounds.
- **Custom range:** use the calendar buttons in the start/end fields to pick a date and 24-hour time (including seconds). Valid changes immediately update graphs and totals; there is no Apply button. You can also type `YYYY-MM-DD`, `YYYY-MM-DD HH:MM` or `YYYY-MM-DD HH:MM:SS`. The end is exclusive; use the next day's date to include a whole day.
- **Graph interval:** damage in a bucket divided by that bucket's duration. Auto uses up to 1,200 buckets. Very broad ranges increase even a manually requested interval to stay within that limit.
- **Group By:** the upper dropdown groups the outgoing graph and Damage totals by **Character**, **Ship type (ship history)**, **Ship class (ship history)**, or **Character Group**. Ship grouping assigns each event to the hull/class observed at that timestamp; missing coverage remains **Unknown ship** or **Unknown ship class**. A character may contribute to several groups after changing ships. Hover counts show selected members in each bucket, and colors identify each series. Grouping choices persist across refreshes, range navigation and restarts. **Options** contains the shared **10-second DPS average** and **Target invulnerability indicators** toggles.
- **10-second DPS average:** enabled by default in **Options**, replacing bucket DPS with a trailing average on both graphs. A saved choice to turn it off is retained. Each second includes its own damage and the preceding nine seconds, divided by ten, including idle seconds. Available damage just before the selected range is included in the lookback. Coarser graph intervals display the mean of those rolling rates within each bucket, including partial final buckets. It works with character/ship grouping and either scale; hover values identify the average and show fractional DPS. Damage totals, hit counts and character eligibility stay based on the original selected range. Toggle it off to restore bucket DPS. The option is saved automatically and restored on the next launch; it also survives refreshes and range undo/redo.
- **Move through time:** narrow arrow buttons beside each graph shift both graphs backward or forward by 25% of the current window without changing its width. Steps round to the nearest whole second, with a one-second minimum. Each click switches to a custom EVE time range, updates filters and totals, and joins the same undo/redo history as drag selections. Use **Ctrl+Z / Ctrl+Y** or Windows mouse **Back / Forward** to undo or redo a move. You can pan into empty ranges and return using the arrows or undo.
- **Wheel zoom:** scroll over the plotted area to zoom both graphs around the time beneath the pointer. Wheel up zooms in; wheel down zooms out. The time under the mouse stays at the same horizontal position, within whole-second rounding. To move forward through time, zoom out near the left side, move the mouse right and zoom back in; reverse the sides to move backward. Bounds use whole seconds, with a one-second minimum window. Continuous wheel events separated by at most **600 ms** form one undo/redo action, restoring the range before the gesture or its final range. A longer pause, pan, drag selection, undo or redo starts a separate action. Keyboard shortcuts and Windows mouse Back/Forward use this same grouped history. Filters, EVE time fields and damage totals follow the new window; scale, grouping and averaging options are retained.
- **Damage totals:** damage, hit counts and average DPS for characters or ship groups in the date range, after applying the current filters. Average DPS includes idle time in the entire selected range. Click any column heading to sort; click it again to reverse the order. An arrow marks the active column and direction. Text columns start alphabetically; numeric columns start highest first. Damage and DPS sort by their underlying numeric values, and **Hits out / in** sorts by outgoing hits, then incoming hits. The **Members** column sorts by member count in ship-type or class mode. Headings stay visible while scrolling, and sorting survives refreshes, grouping changes and graph range navigation for the current session.
- **Incoming Group By:** the dropdown above the incoming plot is independent of outgoing grouping and Damage totals. **Character** groups by the receiving log character; **Character Group** combines receiving characters using saved groups (overlapping membership can appear in multiple groups). **Attacking Character** uses the logged pilot name. **Attacking Ship** uses the logged attacker/corporation/hull combination; logs do not provide a unique ship item ID or custom ship name, so same-pilot, same-corporation, same-hull ships are combined. **Attacking Ship Type** combines sources with the same logged hull. **NPC** uses matched NPC names; **NPC Type** uses CCP NPC groups. Sources missing the attribute for a chosen mode stay under **Other / unresolved**. Recognized structures are not treated as pilots. All shared and NPC filters apply before source grouping, bucketing and rolling averages. Hover member counts refer to selected receiving characters. The incoming choice defaults to **Character**, is saved separately, and survives refreshes and range navigation.

English EVE numeric `from` / `to` combat messages are supported, including their formatting tags and UTF-8 or BOM-marked UTF-16 exports. Misses, repairs and capacitor warfare are excluded. Identical duplicate file exports are counted once; overlapping files with different content are separate sessions. Damage exchanged between two of your own characters correctly appears as outgoing for the attacker and incoming for the recipient. Files without a Listener header cannot be assigned to a character and are reported separately. Unreadable files are reported beside the log refresh controls and retried on refresh.

## Current ships through ESI

1. Open **Settings → ESI configuration…** from the menu bar. The **Application** tab contains the public Client ID, callback port, and a live callback URL preview with a copy button. The Client ID defaults to `b680ade5175c4385a1e800b4bedb70bb`. The same dialog is available through **Configure ESI…** in the **ESI & ships** tab.
2. Sign-in uses **PKCE**. To use your own application, follow **Open EVE developer applications**, register a native / desktop application, and enable `esi-location.read_ship_type.v1` and `esi-location.read_location.v1`. Register the exact URL shown in the dialog: **`http://localhost:8080/callback`** by default. The port is configurable from 1 to 65535; the hostname stays `localhost`. Enter the public Client ID and choose **Save application configuration**.
3. In **Character tokens**, choose **Sign in with EVE Online**, select a character in the browser and grant ship and location access. Repeat for each character. Log characters match sign-ins by name, ignoring capitalization.
4. Switch the sidebar grouping to **Ship history** or **Ship class history**. The outgoing graph sums selected members' damage, and the totals tab shows one row per hull or class with a member count. The same options are available in the graphs' **Format options** menu.

Ships and locations refresh every 30 seconds while enabled, or when you choose **Refresh ships & locations**. Hull names and class IDs come from ESI's public universe type endpoint; class names come from its public universe group endpoint. Hull and class lookups are cached for the session. Sign-ins renew automatically, including rotating refresh tokens. HTTP 401 triggers one renewal/retry; ESI rate limits pause further requests. Failed polls and gaps over 90 seconds break observed periods. The last observed ship is assumed for up to **45 seconds** after its last sighting, unless a newer ship is observed first; damage outside that coverage appears under **Unknown ship** or **Unknown ship class**. Older confirmed periods remain usable after a connection becomes stale or is removed. A failed class lookup leaves the confirmed hull available, reports the issue in ESI status and retries on the next ship refresh. Missing class data stays under **Unknown ship class**. **Disconnect** removes the locally saved sign-in; revoke the application's grant in EVE account management if you also want to revoke server-side access.

Sign-in requests `esi-location.read_ship_type.v1` and `esi-location.read_location.v1`. Enable both scopes in your EVE application. Existing or imported ship-only tokens remain usable for ship tracking; sign in again to grant location access. Tokens that already grant location access are recognized automatically. Scope validation requires the ship scope and accepts additional grants in any order. The same validation applies to sign-in, token renewal and imported tokens.

The **Character tokens** tab also supports importing existing access and/or refresh tokens issued for the configured Client ID with the ship scope (and the location scope for location tracking). **Validate and import tokens** identifies the character from a validated access token, or obtains an access token when only a refresh token is supplied. A supplied pair is checked against the same character, and rotated refresh tokens are saved. Import replaces that character's saved tokens. Access-only imports work until expiry and then need another import or sign-in. Entries are masked and cleared after queuing an import or closing the dialog. Saved connections show token expiry and whether automatic renewal is available, with a **Disconnect** action; saved token values are not displayed.

The Client ID and callback port persist across restarts. Existing saved Client IDs are retained; missing IDs adopt the default above, and older settings without a port adopt 8080. Changing the callback port keeps existing character tokens; changing the Client ID requires disconnecting them first. Former client-secret configurations must use a PKCE application and may require signing in again. Legacy client-secret fields are ignored and omitted when settings are next saved.

Outgoing ship grouping uses **recorded ship history at each damage event**, including when a character changes ships inside a graph bucket. Refreshing current ships never assigns the new hull to older damage. Evela cannot recover ship history from before it began recording observations. ESI cannot expose this private data for characters that have not authorized the application. Queries send ESI access tokens and character IDs to CCP; combat logs are never uploaded.

On Windows, client settings and tokens are stored in `%APPDATA%\Evela\esi.dat`, encrypted with Windows DPAPI for the current user. The file is updated atomically and contains no plaintext tokens. Persistent ESI connections currently require Windows; log analysis remains portable. Sign-in uses a temporary listener bound only to IPv4 loopback (`127.0.0.1`) on the configured port, and advertises `http://localhost:<port>/callback`, with OAuth state validation and PKCE. Access tokens are checked against EVE's published RSA/ECDSA keys, issuer, audience, expiry and requested scope.

Reference: [EVE SSO documentation](https://developers.eveonline.com/docs/services/sso/), [ESI overview](https://developers.eveonline.com/docs/services/esi/overview/).

### Ship observation history

Evela saves timestamped ship observations during ship refreshes and uses them to group damage graphs and totals. Open **ESI & ships → Ship history…** to inspect a snapshot of recorded periods, newest first. Each period includes character ID/name, ship item ID, hull type ID/name, ship class ID/name when available, ship name, first/last observed EVE time timestamps and observation count. The viewer shows unresolved hulls by type ID; older sightings without an item ID show **Unknown**.

Consecutive successful sightings of the same character and ship are combined into a compact period. A ship item, hull, name or character-name change starts another period. Failed queries, gaps over 90 seconds, reconnecting and restarting also start new periods. A successful ship query is retained even if the separate public hull-name lookup fails. The stored times are observations of ESI responses, not exact boarding or unboarding times; polling and API caching limit the available evidence.

History is saved atomically with the encrypted settings in `%APPDATA%\Evela\esi.dat`, and survives restarts, token replacement and disconnecting characters. Disconnect removes the saved sign-in while retaining ship history. Upgrading preserves an older saved last-known ship as a single sighting at its original check timestamp; it does not infer any earlier coverage. There is no automatic history expiry.

The timestamp lookup supports character IDs or case-insensitive log character names. It matches observed periods and assumes the same ship for up to 45 seconds after each period's last sighting. A newer observation takes precedence immediately. Times before the first sighting or more than 45 seconds beyond the preceding period remain unknown, as do ambiguous names. The displayed and saved observation timestamps are unchanged by this allowance. Historical attribution happens before bucketing or averaging, so rolling damage stays with the ship assigned to its original event. Older periods missing hull/class metadata are resolved through public ESI lookups by their saved type ID, without changing their observed times. This also works for disconnected characters; use **Refresh ships & locations** to retry missing metadata.

### Location observation history and System filter

Open **ESI & ships → Location history…** to inspect recorded locations, newest first, in the **Game logs** and **ESI observations** tabs. Each ESI period saves the character ID/name, solar system ID/name, station or structure ID when docked, first/last observed EVE time timestamps, and observation count. Current locations are shown alongside current ships. System names come from the public universe systems endpoint and are cached for the session; unnamed systems remain usable by ID and missing names are retried, including for disconnected characters.

ESI location history uses the same storage and timing rules as ship history: consecutive successful sightings of the same location combine, while a system, station, structure or character-name change starts a new period. Failed location queries, gaps over 90 seconds, reconnecting, token replacement and restarting also begin new periods. Ship and location queries succeed independently. A failed system-name lookup retains the confirmed location ID. History is saved atomically in the same encrypted `%APPDATA%\Evela\esi.dat` file and survives disconnects and restarts without automatic expiry.

The **System** filter supports search, **All**, individual selections and **Unknown system**, with choices saved across restarts. Selected systems combine with OR and intersect the other filter categories. Each damage event and structure marker is matched to the character's historical location at its original timestamp, before bucketing or averaging. When logs do not establish a location, the last ESI location is assumed for up to 45 seconds, until a newer observation begins. Events before tracking, outside coverage or with ambiguous character names remain unknown. Stored observation timestamps are never extended, and refreshing a current location does not assign it to earlier damage.

Game-log locations take priority over ESI, even if a newer ESI poll still reports a cached system. Supported English messages include:

- `Jumping from Mamet to Hoshoun`
- `A Conduit Field activated by Clento Loso jumps you to Mai.`
- `Activating a Conduit Field jumps you to Camal, bringing along 22 passengers.`

The destination applies from the message timestamp until the next logged movement within that session. A jump origin also identifies the system between session start and the first jump. Before a first conduit message, the previous system stays unknown unless ESI provides it. Location coverage follows the session's timestamped entries, with a 45-second allowance after its last entry; it is not carried indefinitely across offline gaps. Names, including multiword and wormhole systems, work without an ESI sign-in. Once ESI supplies a matching system ID, the filter combines both sources into one option and keeps the existing selection.

Log movement events and session bounds are saved in the same encrypted `esi.dat` history, including characters without ESI accounts. Repeated refreshes and duplicate/overlapping exports do not duplicate movement events. Growing logs extend their existing session. Saved log locations remain available after the source files fall outside the loading limit or are removed. **Game logs** shows the derived coverage intervals; **ESI observations** retains the original sampled data. Both damage graphs, totals, rolling averages and structure markers use the same preference for logs.

## NPC data source

CCP publishes the [official Static Data Export](https://developers.eveonline.com/docs/services/static-data/). The embedded `npc_data.json.gz` is generated from JSONL SDE **3607705**, released **2026-10-12**, and contains **7,418 NPC types** and **415 groups**. It joins `types.groupID` to `groups._key`, retaining groups in the **Entity** category (`categoryID = 11`). Unpublished types are included: NPCs such as Amarr Sentry Gun are marked `published: false`. All supplied name translations are indexed. EVE Online and its game data are copyright CCP hf.

Combat logs usually supply display names without type IDs. Matching uses exact names ignoring capitalization and surrounding whitespace, after removing weapon/hit-quality suffixes. Corporation/hull suffixes identify player-owned sources before NPC matching. A shared display name resolves only IDs common to every candidate; conflicting NPC groups appear as **Ambiguous NPC type**. Unmatched names stay in **Other / unresolved**, including new NPCs introduced after the bundled snapshot. No faction, hull, or NPC status is guessed for unmatched names. English combat messages remain required. Resolution is entirely local and needs no ESI sign-in or runtime download.

To update, download CCP's [latest JSONL SDE](https://developers.eveonline.com/static-data/eve-online-static-data-latest-jsonl.zip) into `.cache`, then regenerate, verify and rebuild:

```powershell
go run ./tools/npcdata -sde .cache/eve-sde-<build>-jsonl.zip
go test ./...
go build -ldflags="-H=windowsgui" -o evela.exe .
```

The generator reads build/release metadata from the archive; update the version/counts above when replacing the snapshot. Only compact names, type IDs and group names/IDs are embedded; the full archive is excluded from version control.

## Build and verify

Requires Go 1.23+ and Fyne's desktop build prerequisites (a C compiler; MinGW GCC on Windows).

```powershell
go test ./...
go build -ldflags="-H=windowsgui" -o evela.exe .
```

The application and Windows executable use `icon.svg`. After changing the SVG, run `go generate .` to regenerate `icon.ico` and `icon_windows_amd64.syso`, then rebuild with the command above. Icon resource generation requires MinGW `windres`.

The tests use local mock SSO/ESI servers and fake credentials to verify login, token validation/renewal, encryption, ship changes, rate limits and grouping. DPAPI tests require access to the Windows user's encryption profile; restricted sandboxes may require running the tests outside that sandbox.

An optional read-only integration test checks a real archive:

```powershell
$env:EVELA_TEST_LOGS = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'EVE\logs\gamelogs'
go test -run TestLocalLogs -v
```
